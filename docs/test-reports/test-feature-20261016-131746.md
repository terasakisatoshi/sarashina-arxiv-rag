## Per-Feature Details

### chat (CLI)
- **Role:** Developer new to the project, reads only the README.
- **Use Case:** Install, configure, and run the documented `chat` commands.
- **Discoverability:** Yes. The previous fixes landed: the README now has a `git clone` + `cd` + `uv sync` sequence, a non-destructive `[ -f .env ] || ...` key step, and a cwd warning. The doer could reconstruct the full setup path from docs alone.
- **Setup:** Works as described (external-downstream install verified).
- **Functionality:** Entry point + all documented flags resolve; graceful error when no key. Live API call not run (blocked precondition).
- **Expected vs Actual:** Met.
- **Blocked steps:** Live `chat` call (network + real secret).
- **Friction points:** Python 3.14/`uv` provisioning still assumed; no machine-readable output documented; no manifest contents shown.
- **Doc suggestions:** Note how Python 3.14 is obtained; state that output is human-readable stdout.

### translate (CLI)
- **Role:** Developer new to the project.
- **Use Case:** Run the documented `translate` commands incl. `--from`/`--to` behavior.
- **Discoverability:** Yes. Setup path and language-resolution rules are recoverable; the added `--from ja` example and stdout note helped.
- **Setup:** Works.
- **Functionality:** Entry point + `--from`/`--to` resolve; language resolution matches source.
- **Expected vs Actual:** Met.
- **Blocked steps:** Live call.
- **Friction points:** Behavior when **both** `--from` and `--to` are given (or equal, or invalid) is undocumented; whether `translate` accepts `--api-key` is not stated in its section (it does).
- **Doc suggestions:** State the `--api-key` support and the both-flags behavior.

### pdftranslate (CLI)
- **Role:** Researcher new to the project.
- **Use Case:** Translate a local PDF and an arXiv URL with `--pages` and `--html`/`--pdf`.
- **Discoverability:** Partial. Input formats, arXiv rewrite, and page ranges are clear. **The output file names are not**: default output (`<input>.md`), and the HTML/PDF sidecar naming (`output.with_suffix(".html"/".pdf")`), are undocumented — so the promised `--html`/`--pdf` artifacts cannot be located from docs alone.
- **Setup:** Works (entry point + flags verified).
- **Functionality:** Command forms are accurate; `--html`/`--pdf` flags exist.
- **Expected vs Actual:** Partial — commands are runnable but the produced artifact paths are unpredictable from docs.
- **Blocked steps:** Live run (network + secret + a real PDF).
- **Friction points:** Default/sidecar filenames undocumented; `--html`/`--pdf` produce a "translated-only" PDF / bilingual HTML but the distinction is only partly stated.
- **Doc suggestions:** Document the default output name and the sidecar naming for `--html`/`--pdf`.

### sarashina-web (REST API)
- **Role:** Developer new to the project.
- **Use Case:** Start the service and call each documented endpoint.
- **Discoverability:** Partial. Starting the server and the endpoint table are clear, but the **REST request/response bodies are essentially unspecified**. A doer could not determine the `/api/chat` request field name (README prose says "質問" ⇒ it guessed `question`, but the real field is `message`) or the `/api/index` body fields, terminal `status`/`phase` values, or SSE framing.
- **Setup:** Works. Server boots on `127.0.0.1:8000`; `uv run sarashina-web` and the uvicorn form both valid.
- **Functionality:** Server smoke test passed — `GET /` → 200 HTML; `GET /api/index/{bad}` → 404 `{"detail":"unknown job"}`; `GET /api/paper/{bad}` → 404; `POST /api/chat` unknown job → 404. All documented endpoints exist. Full index→chat flow not run (network + secret).
- **Expected vs Actual:** **Not met.** The README documents `GET /api/paper/{job_id}` as "抽出した原文の HTML を返す", but the implementation returns **JSON** (`{"title", "chunks", "translations"}`). A client written from the docs would break on the first endpoint it tries. Additionally, `/api/index` and `/api/chat` request bodies are undocumented, so the core flow is not callable from docs alone.
- **Blocked steps:** Live index/chat (network + secret).
- **Friction points:** `/api/paper` response described incorrectly; request bodies absent; no documented status/phase values or SSE event format; error shapes undocumented.
- **Doc suggestions:** Fix the `/api/paper` description; document each request body and response shape; list the terminal `status`/`phase` values; document the SSE `data:` framing.

## Issues Found

Ordered by severity:

1. **(Critical, docs) `/api/paper/{job_id}` documented as returning HTML, actually returns JSON.** README §REST API table describes it as "抽出した原文の HTML を返す"; source (`webapp.paper`) returns `{"title","chunks","translations"}` as JSON. A docs-following client breaks. — README L94; `webapp.py:275-290`.
2. **(Critical, docs) `/api/index` and `/api/chat` request bodies undocumented.** No field names for the index URL/page range or the chat message (doer guessed `question`; real field is `message`). The core RAG REST flow is not usable from docs alone. — README L88-96; `webapp.py:83-99`.
3. **(High, docs) Endpoint table incomplete.** The service also exposes `POST /api/translate` and `POST /api/suggest`, absent from the table. — `webapp.py:293,392`.
4. **(Medium, docs) pdftranslate output filenames undocumented** (default `<input>.md`; `--html`/`--pdf` sidecars derived via `with_suffix`). — README L54-64; `pdftranslate.py:306-320`.
5. **(Low, docs) translate `--api-key` support and both-flags behavior unstated.** — README L44-52.
6. **(Low, docs) No dependency manifest / Python 3.14 provisioning shown** (recurring; low impact now that setup is documented).

**Misleading-doc findings (refuted/downgraded candidates → signposts):**

- Doer could not determine the `/api/paper` payload → because the README's "HTML" claim is simply wrong. Signpost — correct the table to describe the JSON payload.

## Suggestions

Ordered by impact:

1. Fix the `/api/paper/{job_id}` row — it returns JSON `{"title","chunks","translations"}`, not HTML.
2. Add a request/response section (literal field names) for `/api/index` and `/api/chat`; include terminal `status`/`phase` values and the SSE `data:` framing.
3. Add `/api/translate` and `/api/suggest` to the endpoint table.
4. Document `pdftranslate` default output (`<input>.md`) and the `--html`/`--pdf` sidecar naming.
5. Note `translate` accepts `--api-key` and define the both-flags/`--from == --to` behavior.
6. Consider a checked example (script or OpenAPI `/docs` cross-link) so the REST shapes cannot rot.
